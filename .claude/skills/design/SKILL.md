# Design

## When to use this skill

- Doing UX/UI, visual, or interaction design work, or building/extending a design system.

## Checklist / best practices

- Frame the user problem before proposing a solution.
- Design for every state - empty, loading, error, success - not just the happy path.
- Use existing design tokens/components rather than inventing new one-off values.
- Check color contrast and touch-target sizes against WCAG 2.1 AA.
- Design flows that work via keyboard and screen reader, not visually only.
- Produce a handoff spec detailed enough to implement without repeated back-and-forth.
- Validate design direction against real user evidence where it exists.

## Common pitfalls

- Designing only the primary/happy-path state.
- Conveying meaning through color alone.
- Introducing a new visual pattern that duplicates an existing design-system component.
- A handoff spec too vague to implement consistently.

## Standards & references

- WCAG 2.1 AA as the accessibility baseline.
- The project's existing design system/token set as the source of truth.
