# Documentation

## When to use this skill

- Writing or updating a README, technical guide, API documentation, or other technical writing.

## Checklist / best practices

- Verify technical claims/instructions against the actual code or system, not memory.
- Match content to the target audience's existing knowledge level.
- Structure for scanning (headings, examples) as well as linear reading.
- Keep a single source of truth - link instead of duplicating content across docs.
- Update documentation in the same change that makes it inaccurate.
- Include working examples, not just abstract descriptions.
- Document error cases and edge behavior, not just the happy path.

## Common pitfalls

- Documentation that describes aspirational, unimplemented behavior as if it exists.
- Setup instructions that were never actually tested.
- Stale docs left behind after a change makes them wrong.
- Duplicated content across multiple docs that drifts out of sync.

## Standards & references

- Docs-as-code: documentation changes reviewed alongside the code changes they describe.
